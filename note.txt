1. Gambaran besar struktur ArtSpace
ArtSpace adalah website portofolio kreatif. Berdasarkan isi proyek, aplikasinya memiliki fitur untuk:
- Menampilkan galeri karya kreatif.
- Mencari dan memfilter karya.
- Melihat detail karya dan profil kreator.
- Mendaftar dan masuk akun.
- Menyukai, menyimpan, dan mengomentari karya.
- Mengunggah serta mengelola karya sendiri.
- Mengakses area Studio dan fitur kolaborasi.
Struktur utamanya seperti ini.
ArtSpace

src/app/
Halaman, routing, layout, API, dan CSS global.

Prioritas 1

src/components/
Komponen antarmuka yang bisa dipakai ulang.

Prioritas 1

src/lib/
Logika aplikasi, data, penyimpanan, validasi, dan utilitas.

Prioritas 1

src/types/
Definisi bentuk data menggunakan TypeScript.


tests/
Pengujian fungsi aplikasi.


File konfigurasi di root
Pengaturan Next.js, TypeScript, dependensi, dan linting.




Cara termudah memahami struktur ini adalah membayangkan sebuah restoran:
- app adalah ruang dan jalur yang bisa dikunjungi pelanggan.
- components adalah meja, menu, tombol, dan bagian tampilan yang digunakan berulang kali.
- lib adalah dapur yang menjalankan proses di balik layar.
- types adalah aturan bentuk data yang boleh digunakan.
- tests adalah pemeriksaan apakah fungsi tertentu bekerja sesuai harapan.
2. Memahami src/app/ — halaman dan routing
Di Next.js App Router, struktur folder menentukan alamat URL. File page.tsx biasanya mendefinisikan halaman, sedangkan layout.tsx membungkus halaman-halaman di dalam lingkupnya.
A. Halaman publik
Lokasi: src/app/(public)/
Folder (public) adalah route group. Tanda kurung membuatnya menjadi pengelompokan internal, bukan bagian dari URL.
File	Fungsi
(public)/page.tsx	Halaman utama galeri ArtSpace (/).
(public)/beranda/page.tsx	Halaman /beranda.
(public)/explore/page.tsx	Halaman eksplorasi, pencarian, atau penyaringan karya (/explore).
(public)/creators/[username]/page.tsx	Profil kreator berdasarkan username.
(public)/projects/[slug]/page.tsx	Detail karya berdasarkan slug.
(public)/contact/page.tsx	Lokasi halaman kontak, tetapi filenya masih kosong.
(public)/layout.tsx	Layout yang digunakan bersama oleh halaman publik.
(public)/loading.tsx	Tampilan sementara saat halaman yang bersangkutan sedang dimuat.
(public)/studio/layout.tsx	Layout untuk jalur Studio di dalam kelompok publik; masih kosong.
Perhatikan dua pola khusus berikut.
[username] dan [slug] adalah dynamic route. Misalnya:
- /creators/alyaputri
- /creators/nadias
- /projects/brand-identity-kopi-senja
Satu file halaman dapat melayani banyak URL, karena nilai di dalam kurung siku diterima sebagai parameter.
Contoh sederhananya:
export default async function Page({
  params,
}: {
  params: Promise<{ username: string }>;
}) {
  const { username } = await params;

  return <h1>Profil {username}</h1>;
}


Contoh tersebut hanya ilustrasi cara kerja dynamic route, bukan pengganti kode profil yang ada di proyekmu.
Yang wajib dipahami: hubungan antara folder, page.tsx, dan URL. Ini adalah dasar navigasi di seluruh ArtSpace.

4. Memahami src/lib/ — logika di balik ArtSpace
Kalau components berfokus pada tampilan dan interaksi, lib berisi aturan serta proses yang mendukung aplikasi.
A. lib/data/ — data awal dan akses data
File	Fungsi
mock-projects.ts	Data contoh karya untuk mengisi galeri selama pengembangan.
mock-creators.ts	Data contoh kreator.
project-detail.ts	Membantu mengambil atau membentuk informasi detail karya.
repository.ts	Lapisan untuk membaca data proyek, memisahkan halaman dari sumber data yang digunakan.
Perbedaan penting:
- Mock data: data contoh yang disediakan di kode.
- Local data: data yang disimpan di browser pengguna.
- Server data: data yang berasal dari backend atau layanan server.
Ketiganya bukan hal yang sama. Karya contoh yang ditulis di mock-projects.ts tidak otomatis menjadi data permanen di database.
B. lib/local/ — penyimpanan lokal
Ini adalah bagian paling penting untuk memahami bagaimana prototipe ArtSpace mempertahankan data tanpa backend.
File	Fungsi
store.ts	Membuat mekanisme penyimpanan lokal yang terhubung dengan React.
auth.ts	Registrasi, login, logout, dan pembacaan pengguna aktif.
projects.ts	Menambahkan, menghapus, dan membaca karya yang diunggah pengguna.
activity.ts	Mengelola suka, simpan, komentar, serta ringkasan aktivitas.
image.ts	Memeriksa, memperkecil, dan mengubah gambar menjadi data URL.
utils.ts	Membuat ID dan mengubah teks menjadi slug.
1. store.ts — mesin penyimpanan
Fungsi utama:
- createLocalStore() membuat store dengan kunci penyimpanan tertentu.
- getSnapshot() membaca data yang tersimpan.
- set() menyimpan data dan memberi tahu komponen yang berlangganan.
- subscribe() mendaftarkan pendengar perubahan.
- useLocalStore() menghubungkan store dengan React.
- useHydrated() mendeteksi apakah aplikasi sudah berjalan di browser.
Store ini memakai localStorage, useSyncExternalStore, dan mekanisme notifikasi perubahan.
Contoh sederhana:
const store = createLocalStore<string[]>(
  "artspace:contoh",
  [],
);

store.set(["Kopi Senja", "Bunga Kristal"]);

const data = store.getSnapshot();


Contoh ini menggambarkan pola yang digunakan store, bukan data yang harus kamu tambahkan ke proyek.
Konsep wajib dipahami: localStorage, JSON, state React, subscription, dan proses hydration. Ini membantu menjelaskan mengapa data bisa tetap tersedia setelah halaman di-refresh.
2. auth.ts — autentikasi lokal
Fungsi pentingnya:
- signUp() membuat akun baru.
- logIn() memeriksa email dan kata sandi.
- logOut() menghapus sesi pengguna aktif.
- getCurrentUser() mengambil pengguna aktif untuk kebutuhan fungsi biasa.
- useAuth() menyediakan informasi pengguna dan status kesiapan browser.
- uniqueUsername() mencari username yang belum digunakan.
Kode menggunakan dua penyimpanan utama:
- artspace:users untuk daftar akun.
- artspace:session untuk ID pengguna yang sedang masuk.
File ini juga memiliki fungsi hash() untuk membuat representasi kata sandi dan toUser() untuk mengubah data akun tersimpan menjadi informasi pengguna yang boleh dipakai aplikasi.
Penting: hash kata sandi di sini tidak menjadikan autentikasi lokal aman untuk produksi. Pengguna dapat memodifikasi penyimpanan browser, dan sistem belum memiliki otoritas backend yang tepercaya. Untuk aplikasi sungguhan, autentikasi dan sesi harus ditangani dengan arsitektur server yang aman.
3. projects.ts — pengelolaan karya
Fungsi yang perlu kamu kenali:
Fungsi	Tugas
isLocalId()	Memeriksa apakah ID menggunakan awalan untuk karya lokal.
toProject()	Mengubah format karya lokal menjadi format Project yang dipakai UI.
addLocalProject()	Membuat dan menyimpan karya milik pengguna aktif.
deleteLocalProject()	Menghapus karya jika dimiliki pengguna yang sedang masuk.
useLocalProjects()	Mengambil daftar karya lokal sebagai hook React.
useAllProjects()	Menggabungkan karya lokal dan daftar proyek yang diberikan oleh pemanggil.
Satu hal penting: toProject() adalah contoh fungsi transformasi data. Data yang disimpan dan data yang dibutuhkan komponen tampilan bisa memiliki struktur berbeda, sehingga fungsi ini menjadi penghubung keduanya.
4. activity.ts — suka, simpan, dan komentar
File ini menjadi pusat aktivitas pengguna. Hook yang terlihat pada proyek antara lain:
- useProjectActivity() untuk membaca status aktivitas terhadap suatu karya.
- useUserActivity() untuk mengambil ID karya yang disukai dan disimpan oleh pengguna aktif.
Operasi tambah/hapus aktivitas juga dikelola di file ini, misalnya fungsi untuk toggle like, toggle save, dan pengelolaan komentar.
Prioritas belajar: pahami bagaimana ID pengguna dihubungkan dengan ID karya. Relasi ini membuat aplikasi bisa membedakan karya yang disukai pengguna A dan pengguna B.
5. image.ts — pemrosesan gambar
Fungsi penting:
- loadImage() memuat gambar yang dipilih.
- processImage() memvalidasi tipe dan ukuran file, mengubah dimensi jika perlu, lalu menghasilkan gambar JPEG.
Kode membatasi file masukan hingga 10 MB, ukuran sisi terpanjang hingga 1.400 piksel, dan menggunakan kualitas JPEG 0,82.
Gambar kemudian dikonversi menjadi data URL. Data ini bisa disimpan di localStorage, tetapi ada batas kuota penyimpanan browser. Itulah sebabnya pemrosesan gambar penting.
6. utils.ts — utilitas data
- newId() membuat ID unik untuk kebutuhan prototipe.
- slugify() mengubah teks seperti Bunga Kristal! menjadi slug seperti bunga-kristal.
Slug berguna untuk URL yang mudah dibaca, sedangkan ID digunakan untuk identitas data.
C. lib/schemas/ — validasi data
File	Fungsi
schemas/auth.ts	Aturan validasi login dan pendaftaran menggunakan Zod.
schemas/project.ts	Validasi unggah karya dan komentar.
schemas/collaboration.ts	Masih kosong.
Contohnya, signupSchema menetapkan bahwa nama harus memenuhi panjang minimal, email harus valid, kata sandi minimal delapan karakter, dan konfirmasi kata sandi harus sama.
Sementara itu, uploadSchema memeriksa judul, disiplin, dan deskripsi karya.
Konsep wajib dipahami: validasi di sisi klien meningkatkan kualitas input, tetapi tidak menggantikan validasi di server. Saat backend ditambahkan, data harus diperiksa kembali di server.
D. lib/search.ts — logika pencarian
Fungsi	Tugas
normalize()	Menyamakan huruf besar/kecil, menghilangkan aksen, dan merapikan spasi.
cleanQuery()	Membersihkan dan membatasi panjang kata kunci.
firstParam()	Mengambil parameter pertama jika nilainya berupa array.
matchesQuery()	Mencocokkan seluruh kata pencarian terhadap kumpulan teks.
Misalnya, pencarian poster hujan dapat menemukan karya berjudul Editorial Poster Musim Hujan, karena setiap kata kunci diperiksa terhadap teks yang tersedia.
File ini menarik untuk dipelajari karena logikanya relatif independen dari React, sehingga lebih mudah diuji.
E. lib/constants.ts dan lib/utils.ts
- constants.ts menyediakan nilai bersama, seperti daftar disiplin karya dan item navigasi.
- utils.ts menyediakan fungsi cn() yang menggabungkan kelas CSS menggunakan clsx dan tailwind-merge.
cn() membantu menggabungkan kelas kondisional sekaligus menangani konflik kelas Tailwind. Kamu akan melihatnya dipakai pada tombol, filter, kartu, dan berbagai komponen UI.
5. Memahami src/types/ — bentuk data aplikasi
TypeScript menggunakan type untuk menjelaskan struktur data yang diharapkan. Ini membantu editor dan compiler mendeteksi kesalahan sebelum aplikasi dijalankan.
File	Fungsi
types/project.ts	Mendefinisikan struktur karya, sampul, warna, dan bentuk dekoratif.
types/creator.ts	Mendefinisikan struktur data kreator.
types/collaboration.ts	Masih kosong.
types/index.ts	Masih kosong.
Contoh dari types/project.ts:
export type Project = {
  id: string;
  slug: string;
  title: string;
  creatorName: string;
  creatorUsername: string;
  discipline: Discipline;
  year: number;
  likes: number;
  tone: Tone;
  shape: Shape;
  cover?: ProjectCover | undefined;
};


Artinya, sebuah Project memiliki ID, judul, nama kreator, disiplin, tahun, jumlah suka, dan atribut tampilan. Sampul bersifat opsional.
Tipe Tone membatasi pilihan warna dekoratif menjadi iris, cobalt, atau berry. Tipe Shape membatasi pilihan bentuk menjadi circles, bars, atau arc.
Mengapa ini penting? Misalnya, kamu tidak sengaja menulis:
tone: "red"


TypeScript dapat menunjukkan kesalahan karena "red" bukan anggota tipe Tone yang didefinisikan.
Prioritas belajar: pahami hubungan antara types/project.ts, lib/data/mock-projects.ts, dan components/projects/project-card.tsx. Ketiganya mewakili bentuk data, sumber data, dan penggunaan data.

8. Alur kerja ArtSpace secara keseluruhan
Sekarang kita gabungkan bagian-bagian tadi. Ini merupakan gambaran hubungan utama antarkomponen dan logika data.
1. Pengguna membuka halaman
src/app/(public)/page.tsx

2. Halaman mengambil atau menggabungkan data
lib/data/ · lib/local/

3. Data ditampilkan melalui komponen
ProjectGrid → ProjectCard → ProjectCover

4. Pengguna melakukan interaksi
Pencarian · suka · simpan · komentar · unggah

5. Logika memvalidasi dan memproses
schemas/ · local/ · search.ts

6. Tampilan diperbarui
React membaca perubahan store dan merender ulang komponen terkait.


Dalam versi prototipe ini, sejumlah data disimpan di browser melalui localStorage. Artinya, alur tersebut belum sepenuhnya bergantung pada backend atau database.
